# 06 - 会话记忆（Chat Memory）

> 对应代码：`MemoryController.java`，配置：`AiConfig.java`

## 功能说明

默认情况下，大模型是**无状态**的——每次请求都是独立的，AI 不记得之前说过什么。
会话记忆（Chat Memory）让 AI 能够"记住"之前的对话内容，实现真正的**多轮对话**。

```
没有记忆：
用户：我叫张三
AI：你好张三！
用户：我叫什么？
AI：抱歉，我不知道你叫什么。（← 忘了！）

有记忆：
用户：我叫张三
AI：你好张三！
用户：我叫什么？
AI：你叫张三。（← 记住了！）
```

## 核心概念

### 组件架构

```
┌──────────────────────────────────────────┐
│             ChatClient                    │
│  ┌────────────────────────────────────┐  │
│  │   MessageChatMemoryAdvisor（顾问）  │  │  ← 拦截请求，注入历史消息
│  │  ┌──────────────────────────────┐ │  │
│  │  │       ChatMemory（记忆）       │ │  │  ← 管理对话历史
│  │  │  ┌────────────────────────┐  │ │  │
│  │  │  │ ChatMemoryRepository    │  │ │  │  ← 存储后端（内存/JDBC）
│  │  │  └────────────────────────┘  │ │  │
│  │  └──────────────────────────────┘ │  │
│  └────────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

| 组件 | 作用 |
|------|------|
| `ChatMemory` | 管理对话历史的接口 |
| `ChatMemoryRepository` | 存储后端（内存/JDBC/Redis） |
| `MessageChatMemoryAdvisor` | Advisor，自动在请求中注入历史消息 |
| `conversationId` | 会话 ID，区分不同用户/对话 |

### 工作原理

```
请求前：
  Advisor 从 ChatMemory 读取 conversationId 的历史消息
  → 将历史消息 + 当前消息一起发送给大模型

请求后：
  大模型生成回复
  → Advisor 自动将 user 消息和 assistant 回复存入 ChatMemory
```

## 配置说明

在 `AiConfig.java` 中配置：

```java
// 1. 记忆仓库（内存版）
@Bean
public ChatMemoryRepository chatMemoryRepository() {
    return new InMemoryChatMemoryRepository();
}

// 2. 会话记忆（保留最近20条消息的滑动窗口）
@Bean
public ChatMemory chatMemory(ChatMemoryRepository repository) {
    return MessageWindowChatMemory.builder()
        .chatMemoryRepository(repository)
        .maxMessages(20)  // 滑动窗口大小
        .build();
}
```

### MessageWindowChatMemory

`MessageWindowChatMemory` 采用**滑动窗口**策略：
- 保留最近 N 条消息
- 超出窗口的旧消息被丢弃
- 避免历史消息过多导致 token 超限

## 接口说明

### 1. 带记忆的多轮对话 `GET /memory/chat`

```
GET /memory/chat?sessionId=user1&message=我叫张三
GET /memory/chat?sessionId=user1&message=我喜欢打篮球
GET /memory/chat?sessionId=user1&message=我叫什么名字？我喜欢什么？
```

代码核心：
```java
String response = chatClient.prompt()
    .user(message)
    .advisors(MessageChatMemoryAdvisor.builder(chatMemory)
        .conversationId(sessionId)  // 绑定会话 ID
        .build())
    .call()
    .content();
```

### 2. 查看会话历史 `GET /memory/history`

```
GET /memory/history?sessionId=user1
```

返回该会话的所有消息记录。

### 3. 清除会话记忆 `GET /memory/clear`

```
GET /memory/clear?sessionId=user1
```

### 4. 无记忆对话（对比） `GET /memory/no-memory`

```
GET /memory/no-memory?message=我叫什么名字？
```

不使用 Advisor，每次都是独立对话，AI 不记得之前的内容。

## conversationId 的作用

`conversationId` 类似 session ID，用于区分不同用户的对话：

```
session1（用户A）：记住A的对话
session2（用户B）：记住B的对话
                     ↑ 互不干扰
```

不同 sessionId 的对话互相隔离，互不干扰。

## 存储后端选择

| 后端 | 特点 | 配置 |
|------|------|------|
| **InMemoryChatMemoryRepository** | 内存存储，重启丢失，适合学习 | 默认 |
| **JdbcChatMemoryRepository** | 数据库持久化，重启不丢 | 需引入 JDBC starter |
| **Redis** | 高性能，适合生产 | 需自行实现 |

### 切换为 JDBC 持久化

1. 添加依赖：
```xml
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-model-chat-memory-repository-jdbc</artifactId>
</dependency>
```

2. 配置数据源后，Spring AI 会自动创建表并使用 JDBC 存储

## 学习要点

1. `MessageChatMemoryAdvisor` 是实现记忆的关键 Advisor
2. `conversationId` 区分不同会话
3. `MessageWindowChatMemory` 使用滑动窗口避免 token 超限
4. `InMemoryChatMemoryRepository` 适合学习，生产用 JDBC
5. 可以通过 `chatMemory.get(sessionId)` 和 `chatMemory.clear(sessionId)` 管理记忆
